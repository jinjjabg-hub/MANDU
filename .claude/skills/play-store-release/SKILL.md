# 플레이스토어 출시 절차 (웹앱 → TWA)

> 상태: **초안**. 멀티타이머(`com.tm.multitimer`)를 출시하며 겪은 내용을 정리했다. 프로덕션 승인 전까지의 경험만 반영되어 있고, 아래 "미검증" 항목은 확인 후 보완한다.

## 방식 한 줄 요약
플레이스토어에 올리는 것은 웹주소가 아니라, PWABuilder가 만든 **AAB 껍데기**다. 앱을 열면 껍데기가 웹사이트를 주소창 없이 보여 준다(TWA). 그래서 화면 수정은 웹사이트만 고치면 반영되고 스토어 재심사가 필요 없다. 인터넷이 없으면 못 쓴다.

## 사용자 대응 원칙
- 사용자는 코딩 경험이 없다. 클릭 순서를 번호로 짧게 안내하고, 입력할 값은 코드 블록으로 준다.
- 화면 캡처가 오면 **읽은 내용을 먼저 말하고** 다음 한 단계만 안내한다.
- **비밀번호, 키 파일, 전화번호가 캡처에 보이면** 반복해서 쓰지 말고 "다시 공유하지 말라"고 알린다.
- 콘솔 화면 문구는 바뀔 수 있으니 "다르게 보이면 캡처를 보내 달라"고 덧붙인다.
- 사람이 해야 하는 일(개발자 계정 가입, 본인 확인, 결제)은 대신하지 말고 안내만 한다.

## 0. 사전 준비 (저장소 쪽, Claude가 한다)
1. 웹앱이 HTTPS로 서비스되고 `manifest.json`이 있다: `id`, `name`, `start_url`, `scope`, `display: standalone`, `lang`, 아이콘 192/512(`any`)와 512(`maskable`), `theme_color`.
2. **개인정보처리방침 페이지**를 공개 주소로 만든다. 수집 항목(없으면 없다고), 외부 서비스(Firebase 등), 보관·삭제, 문의 이메일을 쓴다. 문의 이메일은 **공개된다는 것을 사용자에게 확인**한 뒤 넣는다.
3. 스토어 그래픽을 만든다(Pillow, Playwright).
   - 앱 아이콘 512×512 PNG(1MB 이하), 홍보 그래픽 1024×500, 휴대전화 스크린샷 최소 2장(1080×1920 권장, 9:16).
   - 스크린샷은 360×640 뷰포트에 deviceScaleFactor 3으로 찍는다. 화면이 길면 해당 화면만 CSS로 줄여서 한 장에 담는다.
   - 한글 글꼴이 필요하면 `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`를 쓴다(이 환경 기준).
4. 스토어 문구(앱 이름 30자, 간단한 설명 80자, 전체 설명 4000자)를 `store/listing-ko.md`에 정리한다. **실제 있는 기능만** 쓴다.
5. 이 환경(클라우드 샌드박스)에서는 `gstatic.com`, `github.io`, `play.google.com`에 접속이 막혀 있을 수 있어 **배포된 사이트와 스토어 페이지는 직접 못 열어 본다**. 사용자에게 확인을 부탁한다.

## 1. PWABuilder로 AAB 만들기
1. https://www.pwabuilder.com 에 사이트 주소 입력 → Start → Package for stores → Android → Google Play.
2. 입력값

| 칸 | 값 | 주의 |
|---|---|---|
| Package ID | `com.회사.앱이름` | **기본값(`io.github....twa`)으로 자동 채워진다.** 반드시 바꾼다. 뒤로 갔다 오면 다시 기본값으로 돌아갈 수 있다. 스토어에 올린 뒤에는 변경 불가 |
| App name / Short name | 앱 이름 | 한글 가능 |
| App version / code | `1.0.0` / `1` | 업데이트 때 code를 올린다 |
| Signing key | New | |
| Key alias | 영문 소문자 | |
| Key full name | 영문 (`Appname Admin`) | **한글 금지** |
| Key organization | 영문 약어 | **한글 금지** |
| Key organizational unit | `Engineering` | |
| Key country code | `KR` | **대문자 2글자** (`ks` 같은 오타 주의) |
| Google Play billing / ChromeOS only / Meta Quest | 체크 안 함 | |

3. 다운로드한 zip을 풀면 `.aab`(업로드용), `.apk`(내 폰 테스트용, 스토어에는 올리지 않음), `signing.keystore`, `signing-key-info.txt`, `assetlinks.json`이 있다.
4. **검증:** `assetlinks.json`의 `"package_name"`이 의도한 Package ID인지 메모장으로 확인한다. 다르면 처음 받은 zip은 **버리고** 다시 만든다.
5. **키 보관:** `signing.keystore`와 `signing-key-info.txt`는 구글 드라이브(비공개)와 USB 두 곳에 보관한다. GitHub, 카톡에는 올리지 않는다.

## 2. Play Console
(개발자 계정 가입: 등록비와 본인 확인이 필요하며 사용자가 직접 한다.)

### 2-1. 앱 만들기
- 앱 이름, 기본 언어 **한국어 – ko-KR**, **앱**, **무료**, 정책 체크.
- **패키지 이름 칸에는 앱 이름이 아니라 Package ID**를 넣는다(한글을 넣으면 `com.example.myapp` 형식 오류가 난다).

### 2-2. 앱 콘텐츠 선언 (대시보드의 "앱 설정")
| 항목 | 값(멀티타이머 기준) |
|---|---|
| 개인정보처리방침 | 공개 주소 |
| 앱 액세스 | 로그인 없이 모든 기능 사용 |
| 광고 | 없음 |
| 광고 ID | 사용 안 함 |
| 콘텐츠 등급 | 설문 전부 "아니요" |
| 타겟층 | 18세 이상만(아동 정책 부담을 피하는 가장 단순한 선택) |
| 데이터 보안 | 수집한 것만 정확히 답한다(예: Firebase 익명 ID, 사용자가 입력한 명단). 전송 암호화 예, 삭제 요청 방법 기재 |
| 정부 앱 / 금융 기능 / 건강 앱 | 해당 없음 |

### 2-3. 스토어 설정과 등록정보
- 스토어 설정: 앱 카테고리 **도구**(또는 생산성), 연락처 이메일(필수), 전화번호와 웹사이트는 선택이다. **스토어에 공개되므로** 전화번호는 비우는 것을 권한다.
- 기본 스토어 등록정보(ko-KR): 앱 이름, 간단한 설명, **전체 설명(필수)**, 아이콘, 그래픽 이미지, 스크린샷 → "리뷰" 단계 → **AI 애셋 선언**(코드로 직접 그린 이미지면 "라벨 지정 안 함") → 저장.

### 2-4. 비공개 테스트
1. 테스트 및 출시 → 테스트 → 비공개 테스트 → 국가/지역에서 **대한민국** 선택.
2. 테스터: **이메일 목록**을 만들고(이메일은 Gmail 계정이어야 한다), 목록에 체크한다. **의견 URL 또는 이메일**(필수)을 입력한다.
3. 새 버전 만들기 → **App Bundle에 `.aab` 업로드** → Play 앱 서명 안내는 "계속" → 출시명(관리용) → 출시 노트(`<ko-KR>` 태그 사이에 쓴다) → 다음 → 오류 0개 확인 → 저장 → 출시 시작(Google에 전송).
4. 개발자 계정의 Gmail도 테스터 목록에 **직접 추가**해야 설치할 수 있다.

## 3. 자주 만난 오류와 해결
| 증상 | 원인 | 해결 |
|---|---|---|
| 패키지 이름이 `com.example.myapp` 형식이어야 한다 | 앱 이름을 넣음 | Package ID 입력 |
| "APK 또는 App Bundle을 업로드해야 합니다" 외 2개(업그레이드 불가, 번들 추가·삭제 안 함) | 이 버전에 AAB가 없음 | AAB 업로드(오류 3개는 한 원인) |
| "아직 앱을 게시할 수 없습니다" | 대시보드 앱 설정 미완료 | 2-2, 2-3 완료 |
| "전체 설명을 추가하세요" | 등록정보 전체 설명 비어 있음 | 문구 입력 |
| 금융 기능 / 건강 앱 선언 필요 | 선언 미작성 | "해당 없음"으로 작성 |
| (경고) 광고 ID 선언 | 선언 미작성 | "사용 안 함" |
| 링크 복사 버튼이 회색 | 아직 게시(검토 통과) 전 | 게시 개요에서 상태 확인, 기다림 |
| 옵트인 링크에서 "항목을 찾을 수 없음" / "앱을 사용할 수 없습니다" | 로그인한 계정이 테스터 목록에 없음, 또는 `details?id=` 주소로 열었음 | 목록의 Gmail과 로그인 계정을 맞추고, **옵트인 링크**로 연다 |

## 4. 테스터 모집
- 링크는 비공개 테스트 → 테스터 탭 → 테스트 참여 방법 → **Android에서 참여 → 링크 복사**(옵트인 링크). 게시 후에만 활성화된다.
- `play.google.com/store/apps/details?id=패키지` 주소는 **테스터 등록 후에야** 설치 버튼이 보인다. 처음 안내용으로 쓰지 않는다.
- 안내문 요소: 어떨 때 쓰면 좋은지(사용 상황), 설치 3단계, "테스트 기간 동안 삭제하지 말 것", Gmail 미등록 시 주소 요청, 아이폰은 웹 버전(홈 화면에 추가).

## 5. 주소창 없이 열리게 하기 (assetlinks.json)
1. Play Console → 앱 무결성 → **앱 서명 키 인증서 SHA-256 지문**을 사용자가 복사해 준다.
2. `https://도메인/.well-known/assetlinks.json` 이 열려야 한다. GitHub Pages 프로젝트 주소(`user.github.io/repo/`)는 **도메인 루트**에 파일이 있어야 하므로 `user.github.io` 저장소에 올린다.
3. 같은 저장소에 빈 파일 `.nojekyll`이 필요하다(점으로 시작하는 폴더가 배포되도록).
4. **기존 파일이 있으면 덮어쓰지 말고 항목을 추가**한다(다른 앱이 같은 파일을 쓸 수 있다).
5. 업로드 키와 앱 서명 키가 다르므로, 지문 두 개를 모두 넣어야 할 수 있다(미검증).
6. 이 저장소에 쓸 권한이 세션에 없으면 사용자에게 파일 내용을 주고 올리는 방법을 안내하거나 저장소 연결을 요청한다.
- 서식 템플릿: `store/assetlinks.template.json`

## 6. 프로덕션 신청과 이후 (미검증)
- 개인 개발자 계정은 비공개 테스트를 먼저 거쳐야 프로덕션 액세스를 신청할 수 있다는 안내가 대시보드에 표시된다. **필요한 테스터 수와 기간은 콘솔 안내 문구를 기준으로** 확인한다(정확한 수치를 확인하지 못했다).
- 테스트 기간 동안 테스터가 앱을 유지하도록 안내한다.
- 프로덕션 신청 화면의 항목과 심사 소요 시간은 **미검증**: 실제 진행 후 이 문서에 기록한다.
- 웹을 수정해도 스토어 재심사는 필요 없다. 단 매니페스트의 패키지, 서명, 권한 등 **앱 껍데기가 바뀌면** 새 AAB(version code 증가)를 올려야 한다.

## 미검증 항목 (진행하며 채울 것)
- [ ] 프로덕션 액세스 신청 조건과 소요 시간
- [ ] `assetlinks.json` 적용 후 주소창이 사라지는지
- [ ] 업로드 키 / 앱 서명 키 지문 둘 다 필요한지
- [ ] 업데이트 배포 때의 순서(version code, 출시 노트)
